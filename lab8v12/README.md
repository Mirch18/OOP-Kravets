# Лабораторна робота №8

**Тема:** Делегати й лямбда-вирази у практиці колекцій: `CollectionHelper<T>`.

**Мета:** Навчитися передавати поведінку як параметр через делегати `Func`, `Action`, `Predicate`, будувати на цій основі універсальні операції над колекціями та використовувати лямбда-вирази у практиці ООП (варіант 12: `CollectionHelper<T>` з методом `OrderBy`).

## Хід роботи

У ході виконання роботи за допомогою .NET CLI у директорії `OOP-Kravets` було створено консольний проєкт `lab8v12`.

У файлі `Program.cs` реалізовано:

- **Статичний узагальнений клас `CollectionHelper<T>`** з методом згідно з варіантом:

  ```csharp
  public static IEnumerable<T> OrderBy<TKey>(IEnumerable<T> collection, Func<T, TKey> keySelector)
      where TKey : IComparable<TKey>
  ```

  Метод сортує елементи колекції за зростанням ключа, який повертає делегат `keySelector`. Готовий LINQ-оператор `OrderBy` не використовується — сортування реалізовано власним кодом:

  1. Елементи колекції копіюються в новий список, тому початкова колекція не змінюється.
  2. Для кожного елемента один раз обчислюється ключ через `keySelector`.
  3. Список сортується **сортуванням вставками**: кожен наступний елемент зсувається ліворуч, доки ключ попереднього елемента більший за його ключ. Порівняння ключів виконується через `CompareTo`, що доступний завдяки обмеженню `where TKey : IComparable<TKey>`.
  4. Сортування стабільне: елементи з однаковими ключами зберігають початковий порядок.

  Також оброблено граничні випадки: порожня колекція повертає порожній результат, `null` замість колекції або делегата викидає `ArgumentNullException`, ключ `null` вважається найменшим.

- **Клас `Product`:** властивості `Name`, `Category`, `Price`, конструктор і перевизначений `ToString()`.

У точці входу `Main` метод `OrderBy` викликано для колекцій різних типів з передаванням лямбда-виразів:

1. `List<string>` — сортування рядків за довжиною (`word => word.Length`); рядки однакової довжини залишаються в початковому порядку.
2. `List<Product>` — сортування продуктів за ціною (`product => product.Price`) та за назвою (`product => product.Name`).
3. `List<int>` — сортування чисел за значенням (`number => number`) та за модулем (`number => Math.Abs(number)`).
4. Порожній `List<int>` — перевірка граничного випадку.

## Відповіді на контрольні запитання

1. **Що таке делегат і для чого він використовується?**

   Делегат — це тип, який представляє посилання на метод з певною сигнатурою (типами параметрів і типом результату). Змінна-делегат може зберігати метод і викликати його пізніше. Делегати дають змогу передавати поведінку як параметр: у роботі метод `OrderBy` не знає, за чим сортувати, — це визначає делегат `keySelector`, який передається під час виклику.

2. **У чому полягає різниця між `Func` та `Action`?**

   `Func` — узагальнений делегат для методів, що повертають значення: останній тип-параметр є типом результату (наприклад, `Func<T, TKey>` приймає `T` і повертає `TKey`). `Action` — делегат для методів, що нічого не повертають (`void`), наприклад `Action<string>` приймає рядок і лише виконує дію. Окремо є `Predicate<T>` — делегат, що приймає `T` і повертає `bool`.

3. **Як лямбда-вирази спрощують роботу з делегатами?**

   Лямбда-вираз дає змогу описати метод прямо в місці виклику, без оголошення окремого іменованого методу. Замість створення методу `GetLength(string word)` достатньо написати `word => word.Length`. Компілятор сам визначає типи параметрів і результату, тому код стає коротшим і легшим для читання.

4. **Які переваги дають узагальнені методи при роботі з колекціями?**

   Узагальнений метод пишеться один раз і працює з колекціями будь-якого типу: в роботі той самий `OrderBy` сортує `List<string>`, `List<int>` і `List<Product>`. Тип перевіряється під час компіляції, тому не потрібно приведення типів, а помилки виявляються ще до запуску програми. Разом із делегатами це дає змогу створювати універсальні операції, поведінку яких задає код, що їх викликає.
